# BottleRefund 玻璃瓶回收

- 作者: 词库助手
- 适用: TShock 6.x · Terraria 1.4.5.x
- 功能: **玩家每喝一瓶药水，延迟几秒后自动返还一个玻璃瓶**。发放前对整段时间窗的背包流水做全面结算，
  合并堆叠、快速堆放入箱、移入银行、整组丢弃、扔垃圾桶等批量操作**不会误发**；无任何游戏内指令。

## 为什么这样做

泰拉瑞亚多人模式里"喝药"是客户端权威行为：药水在客户端本地扣减，服务器唯一能看到的痕迹是随后的
背包槽同步包（PlayerSlot）。但"堆叠减少 ≠ 喝药"——所有批量整理操作都会让堆叠下降。因此插件采用
**延迟结算窗口**：把窗口内三个来源的流水攒起来统一核算，而不是逐包即时判断。

## 流水来源与结算规则

| 来源 | 内容 |
| --- | --- |
| `PlayerSlot` | 主背包槽（不含垃圾桶 58 与猪猪银行等 Bank 槽）的药水增减 |
| `ItemDrop` | 药水丢在地上 |
| `ChestItemChange` | 药水存入箱子（正变化） |

结算（静默且最老一笔达到结算延迟后，按药水类型逐一配对）：

1. 槽位减少 ↔ 等量、时间靠后的槽位增加 → **移动/合并**，不返还；
2. 槽位减少 ↔ 箱子存入 → **入箱**，不返还；
3. 槽位减少 ↔ 地面丢弃 → **丢弃**，不返还；
4. 剩余减少中**每笔恰好 1** 的判定为喝药；>1 的未配对批量残留不返还。

连按 H 快速喝完一整组：每次都是独立的 -1，各返还一次。

"药水类物品"在启动时全物品扫描：`potion==true`（治疗系）∪ `buffType>0 && consumable`（增益系），
并排除食物（`IsFood`）。**瓶装水不在集合内**——酿造药水消耗瓶装水的 -1 不会误判；吃饭也不触发。

## 配置

文件：`tshock/BottleRefund.json`，首次运行自动生成；**修改后重启服务器生效**（无游戏内指令）。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `启用` | `true` | 总开关 |
| `返还概率` | `1.0` | 每喝一瓶的返还概率（0~1） |
| `每次喝药返还数量` | `1` | 每瓶药返还的物品数量 |
| `返还物品ID` | `31` | 默认玻璃瓶；也可配成其它物品（如 126 瓶装水） |
| `结算延迟秒` | `8.0` | 窗口越大配对越可靠，但瓶子到账越慢 |
| `药水黑名单` | `[]` | 不参与返还的物品 ID |
| `流水上限` | `300` | 持续批量操作导致流水超限时整批放弃（宁漏勿错） |
| `详细日志` | `false` | 每次结算输出按类型的判定明细 |

## 实现说明

- 主线程泵：`ServerApi.Hooks.GameUpdate` + 原版专用服务器主循环的
  `Main.OnTickForThirdPartySoftwareOnly` 双挂（部分 TSAPI/OTAPI 组合下前者不触发），
  共用一个泵，重复驱动无害。
- 药水集合在 `GamePostInitialize` 重建一次（`ContentSamples` 在 `Main.Initialize` 中段才填充，
  晚于插件初始化），主循环兜底重试直到就绪。
- 服务器侧维护槽位/箱子镜像（绝对值同步包），delta 由镜像差分得出。

## 已知边界（宁漏勿错）

- 拿起药水在光标上停留超过结算延迟再放下 → 可能多返 1 瓶（光标内容服务器不可见）；
- 结算窗内"喝 1 瓶 + 恰好从箱子取出 1 瓶同类"→ 等量配对抵消，漏返 1 瓶；
- 上述均为玻璃瓶级别的微小出入，方向上不会系统性多发。
